# Decision Tree — 起動判定の決定木

本スキルを起動すべきか迷った場合、以下の決定木に従う。

## 第1段階: 目的の判定

```
依頼された文書の主たる目的は何か?

├── 学習・変容・発見が目的
│   （受け手が何かを身につける、態度が変わる、新しい視点を得る）
│   → 第2段階へ
│
└── 決定・実行が目的
    （受け手が判断する、選択する、行動を起こす、契約する）
    → 起動しない（通常の構成で対応）
```

## 第2段階: 文書種別の判定

```
学習・変容が目的の場合、文書種別は?

├── ワークショップ台本
│   → 起動する。templates/workshop-script.md を使う
│
├── 登壇・カンファレンスのプレゼン台本
│   → 起動する。templates/presentation-deck.md を使う
│
├── 解説記事・コラム・ブログ・note記事
│   → 起動する。templates/explainer-article.md を使う
│
├── チュートリアル・ハンズオン
│   → 「原理を発見してほしい」目的なら起動する。templates/tutorial.md
│   → 単なる操作手順なら起動しない（通常の手順書）
│
└── その他
    → 第3段階へ
```

## 第3段階: グレーゾーンの判定

以下のケースは判断が難しい。それぞれの判断基準：

### 提案書・営業資料

```
└── 提案書・営業資料
    ├── 受注前で、意思決定が目的 → 起動しない
    ├── 受注後の納品物の一部（プロジェクトの考え方を伝える） → 起動可
    └── 社内向けの提案（議論・合意形成が目的） → 部分的に起動可
```

判断基準：「読んでサインする」文書か、「読んで考える」文書か。

### 社内資料

```
└── 社内資料
    ├── 議事録・進捗報告 → 起動しない
    ├── 戦略ドキュメント（議論を喚起したい） → 起動可
    └── 制度・運用ルール（決定事項の周知） → 起動しない
```

### ブランド系ドキュメント

```
└── ブランド系
    ├── ブランドガイドライン本体（規定の明示） → 起動しない
    ├── ブランドストーリー・コンセプト記事（受け手に世界観を発見させる） → 起動する
    ├── VIガイドラインの導入部 → 起動しない（規定文書の一部）
    └── ブランド体験設計のナラティブ部分 → 起動する
```

### Hiromiさんの実務での具体例

```
Customer Cloud関連
├── オーバービュー（読み手に概念を発見させる） → 起動可
├── 提案書（意思決定が目的） → 起動しない
└── MOU（契約文書） → 起動しない

Fellows VIS関連
├── ワークショップ台本 → 起動する
├── ワークショップ前の事前共有資料 → 部分的に起動可
└── ワークショップ後の議事録・成果まとめ → 起動しない

E:Stack Theory関連
├── 論文 → 起動しない（学術論文は明示的論理が前提）
├── 普及・啓蒙の解説記事 → 起動する
└── 公式の理論定義ドキュメント → 起動しない
```

## 第4段階: ユーザー指示の優先

ユーザーが明示的に指示した場合、その指示を優先する：

- 「点と線で書いて」「気づかせる構成で」 → グレーゾーンでも起動する
- 「結論先出しで書いて」「論理的に並べて」 → 学習目的でも起動しない
- 「いつも通りで」 → 文脈で判断（Hiromiさんの普段の好みに従う）

## 起動を判断する一行ルール

迷ったら、以下の一行で判断する：

> **受け手の「自分で気づいた感」を最大化したい文書か?**
>
> - YES → 起動する
> - NO → 起動しない
> - 分からない → ユーザーに確認する（Desktopの場合）または起動しない（Codeの場合、保守的に）

## 起動後の中断条件

起動後、以下が判明したら即座に中断する：

- 文書の目的が実は「決定・実行」だった
- 受け手の認知負荷を上げる余裕がないことが分かった（緊急性が高い、時間がない）
- ユーザーが「やっぱり普通の構成で」と要求した

中断時の対応：
- 「目的を再確認したところ、本スキルは適切ではないと判断しました。通常の構成で書き直します」
- 既に生成した内容を、結論先出し型に再構成する
