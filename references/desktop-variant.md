# Claude Desktop Variant — 対話による構成設計

Claude Desktopで本スキルが起動した場合の振る舞いを規定する。

## 基本姿勢

Hiromiさんとの対話を通じて、構成を**一緒に詰めていく**。一気に完成形を出さない。
依頼から完成までの間に、最低1往復は対話を挟む。

## フロー

### Phase 1: 入力確認（必ず行う）

依頼を受けたら、まず以下の4項目を確認する。すでに依頼に含まれているものは省略する。

```markdown
構成を設計する前に、4点だけ確認させてください：

1. **目的**: 今回のテーマで、聴衆/読者に何を持ち帰ってほしいですか?
2. **聴衆**: 誰に向けたものですか? 前提知識はどれくらい?
3. **立ち上げたい結論**: 最後に聴衆/読者の頭の中に1文で立ち上がってほしいことは?
   （※台本には書きません。設計のゴールとして使います）
4. **持ち時間 / 文字数**: どれくらいの規模で?
```

⚠️ 例外：依頼内に十分な情報が含まれていれば、確認せず Phase 2 に進む。「以下の内容で台本を作って」と詳細な指示が来た場合など。

### Phase 2: 結論と点の抽出（提案する）

入力情報をもとに、以下を**提案として**提示する：

```markdown
こんな構成で組もうと思いますが、どうですか?

**立ち上げたい結論（書かない・ゴールとして固定）**:
○○

**配置する点（3〜5個）**:
1. [点①]: [内容]
2. [点②]: [内容]
3. [点③]: [内容]

**意外性のある順序**:
[点②] → [点①] → [点③] の順序にすると、線が繋がる瞬間の快感が強くなります。

**意図的な穴の候補**:
[穴の内容]

ここで一度、Hiromiさんの感覚と合うか確認させてください。
- 結論は意図と合っていますか?
- 点の選択はこれで良さそうですか?
- 順序は他に試したいパターンがありますか?
```

ここで一旦止まり、Hiromiさんの反応を待つ。

### Phase 3: 台本生成

合意が取れたら、適切なテンプレート（`templates/` フォルダ内）を使って台本を生成する。

生成時、テンプレートの **「何を言う/書く」「何を言わない/書かない」** の両方を必ず埋める。空欄のままにしない。

### Phase 4: 生成後のセルフチェック

生成した台本に対して、`SKILL.md` のアンチパターン表で自己チェックする。
問題が見つかれば、修正版を即座に提示する。

### Phase 5: 引き渡し

生成完了後、以下のいずれかを提案する：

- 「ここから `pro-editor` スキルで推敲しますか?」
- 「note記事化するなら `note-article-writer` スキルで文体調整しますか?」
- 「論理整合性を `brand-concept-verifier` スキルで検証しますか?」

## 対話スタイル

- 一気に完成形を出さない
- Phase 2 で必ず一度立ち止まる
- Hiromiさんの反応を見て、点の選択・順序・穴の位置を調整する
- 「これでいいですか?」と確認しすぎない。提案として出して、反応を待つ

## アーティファクト出力

生成した台本は、長文の場合はアーティファクトとして出力する。
短い場合（500字以下）はチャット内で完結させる。

ファイル種別：
- ワークショップ台本 → Markdown
- プレゼン台本 → Markdown
- 解説記事 → Markdown
- チュートリアル → Markdown
