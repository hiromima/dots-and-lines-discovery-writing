# Tutorial Template — 発見駆動型チュートリアル

ハンズオン、操作手順を含むチュートリアル、学習者が手を動かしながら理解していく形式に使用するテンプレート。「**手順の暗記**」ではなく「**原理の発見**」を目的とする場合に発動する。

⚠️ 注意：APIドキュメントや純粋な操作マニュアル（決まった手順を正確に実行することが目的）には発動しない。それらには通常の順序立てた構成（前提→手順→確認）が適切。

## 適用条件

- 「なぜこの手順なのか」を学習者に発見させたい
- 単発の操作ではなく、原理を理解した上で応用できるようになってほしい
- ハンズオンで「ああ、そういうことか」体験を作りたい

## 構造

```markdown
# [チュートリアルタイトル]

## メタ情報
- 目的（学習者に何を持ち帰ってもらうか・どんな原理を発見してほしいか）:
- 想定学習者（前提知識、躓きやすいポイント）:
- 立ち上げたい結論（書かない・学習者が最後に気づいてほしい原理）:
- 所要時間:
- 配置する「気づきポイント」の数:

---

## 構造

### Step 0: 違和感の提示

**学習者がまず触れる体験**:
- うまく動かない例
- 直感に反する結果
- 「あれ?」と思う観察

**やってもらうこと**:
- 一度、間違った方法（または素朴な方法）でやってもらう
- 「うまくいかない」体験を先に作る

**書かないこと**:
- 「正しい方法はこうです」と先に教える
- 答えを先に見せる

---

### Step 1〜N: ハンズオンの各ステップ

各ステップに以下の構造を適用：

#### Step X: [手順名]

**実行してもらうコマンド/操作**:
```bash
# 実行コマンド
```

**この時、学習者の頭の中で起きていること（教える側の認識）**:
- [学習者が「あれ?」と思う瞬間]
- [気づきの起点]

**期待する反応**:
- [「あ、こういうことか」と思ってほしいポイント]

**先に説明しないこと**:
- なぜこれが必要なのかは、まず触らせてから語る
- 結果が出てから「なぜそうなったか」を問う

**問いのプロンプト**:
- 「ここで、なぜこの結果になったと思いますか?」
- 「もしStep Xを省略したら、何が起きると思いますか?」（実際に試させてもよい）

---

### 中盤の振り返り

ハンズオンを3〜5ステップ進めた後、一度立ち止まる。

**やること**:
- 「ここまでで、何か気づいたことはありますか?」
- 学習者が自分の言葉で原理を語ろうとする時間を作る

**やらないこと**:
- 「ここまでの内容は、つまり○○です」とまとめる
- 答え合わせをする

---

### Step N+1: 応用問題

**やってもらうこと**:
- 教えていない応用ケースを、自分で解いてもらう
- ここで「原理を本当に発見していたか」が試される

**学習者の反応パターン**:
- A: スムーズに解ける → 原理を発見できている
- B: 詰まる → どの段階で原理が伝わっていないかをヒアリング

---

### 締め: 言語化の支援

**やること**:
- 学習者の言葉で「結局これは何だったのか」を語ってもらう
- それを整理して見せる（ただし「正解」として与えない）

**フレーズ例**:
- 「ここまでで、皆さん（あなた）の中に立ち上がった原理は、何でしたか?」
- 「もし誰かに今日のことを一行で説明するとしたら、どう言いますか?」

---

## 意図的な穴

チュートリアルにおける穴は、「**最後に学習者が触らないと気づかないパラメータ**」のような形で実装する。

| 項目 | 内容 |
|---|---|
| 穴（あえて触れない設定・概念） | |
| なぜ穴を作るか | |
| いつ気づかせるか（後続のチュートリアル、または現場での実践時） | |

---

## ハンズオン特有の演技指示

- 学習者が詰まっても、すぐに答えを言わない
- 「何を試してみました?」と問い返す
- 答えを教えるのは、学習者が3回試行錯誤した後
- 進度の早い学習者には、応用問題を即座に渡す
- 全員の進度を揃えようとしない

---

## 生成後のセルフチェック

- [ ] Step 0で「うまくいかない体験」を先に作っているか
- [ ] 各ステップで、操作の前に原理を説明していないか
- [ ] 中盤で立ち止まる振り返りを入れているか
- [ ] 応用問題で学習者の発見が試されるか
- [ ] 締めで言語化を学習者に委ねているか
```

## 使い方

1. メタ情報を埋める
2. 学習者に「発見してほしい原理」を1文で確定する
3. Step 0で「うまくいかない体験」または「違和感」を作る
4. 各ステップで「操作→結果→問い」の順序を守る
5. 中盤で振り返りタイムを入れる
6. 応用問題で原理の理解を試す
7. 締めは学習者の言語化に委ねる
